多项式扩展 + LR
    原始
        特征属性: x1、x2、x3
        目标属性: y
        LR预测函数: p = sigmoid(w1*x1+w2*x2+w3*x3)
    二阶的多项式扩展:
        特征属性:
            x1、x2、x3、x1*x2、x1*x3、x2*x3、x1^2、x2^2、x3^2
        目标属性: y
        LR预测函数: p = sigmoid(
                w1*x1 + w2*x2 + w3*x3 +
                w4*x1*x2 + w5*x1*x3 + w6*x2*x3 +
                w7*x1^2 + w8*x2^2 + w9*x3^2
            )
        多项式扩展相当于将坐标系做了一个转换，是从低维到高维的一个映射
        多项式扩展就相当于是一种映射函数(理解成神经元的功能)
            z1=f1(x1,x2,x3)=x1
            z2=f2(x1,x2,x3)=x2
            z3=f3(x1,x2,x3)=x3
            z4=f4(x1,x2,x3)=x1*x2
            z5=f5(x1,x2,x3)=x1*x3
            z6=f6(x1,x2,x3)=x2*x3
            z7=f7(x1,x2,x3)=x1^2
            z8=f8(x1,x2,x3)=x2^2
            z9=f9(x1,x2,x3)=x3^2
    NOTE: 多项式扩展是不是就是将原始的特征属性(x1,x2,x3); 通过映射函数(神经元)映射到(z1,z2,z3,z4,z5,z6,z7,z8,z9)后，就会发现原来线性不可分的数据变成了线性可分。
        eg:
            (1,5,3) -> (1,5,3,5,3,15,1,25,9)
    深度学习：
        个人认为深度学习/神经网络是LR(线性转换+激活函数)的堆叠
        原始数据:
            x1,x2
            p=sigmoid(w1*x1+w2*x2+b)
        二阶多项式扩展数据:
            x1,x2,x1^2、x2^2
            p=sigmoid(w1*x1 + w2*x2 + w3*x1^2 + w4*x2^2 + b)
                z1=f1(x1,x2)=x1
                z2=f2(x1,x2)=x2
                z3=f3(x1,x2)=x1^2
                z4=f4(x1,x2)=x2^2
                p = sigmoid(w1*z1 + w2*z2 + w3*z3 + w4*z4 + b)
        深度学习数据:
            x1,x2 --> z1,z2,z3 --> p
                z1=f1(x1,x2)=tanh(-1.2*x1-0.13*x2-2.0)
                z2=f2(x1,x2)=tanh(-0.58*x1-1.3*x2+3.0)
                z3=f3(x1,x2)=tanh(0.82*x1-1.1*x2-3.0)
                p = sigmoid(-1.7*z1 + 1.8*z2 + -1.8*z3 + 0.0)
            每个神经元的功能就是提取特征信息，对每个样本而言每个神经元(每组参数)相当于从某个方面进行特征的描述/特征的提取；至于每个神经元具体提取什么特征由参数决定，参数又由当前模型的训练数据决定(损失最小化)
        NOTE:
            如果没有激活函数的时候，不管深度学习的网络有多少层，都相当于单层的线性模型
                p = sigmoid(-1.7*z1 + 1.8*z2 + -1.8*z3 + 0.0)
                    = sigmoid(
                            -1.7*(-1.2*x1-0.13*x2-2.0) +
                            1.8*(-0.58*x1-1.3*x2+3.0) +
                            -1.8*(0.82*x1-1.1*x2-3.0) +
                            0.0
                        )
                    = sigmoid(-0.48 * x1 + -0.139 * x2 + 14.2)

知识图谱
    一、构建知识图谱
        依赖最强的两个技术点: 命名实体识别、关系抽取
        命名实体识别：从给定的文本/数据中找出业务关系的实体词语
        关系抽取；在命名实体识别的基础上，判断实体之间的关系
    二、知识图谱的使用
        -1-. 风控：构建企业、老板、借贷、逾期、还款、纠纷、合同等等之间的关系，从而在发生借贷关系的时候，进行风控的评定
        -2-. 故障检测：可以将故障、故障的表现、故障的解决方案等实体之间构建关系，从而自动化的进行故障检测；当设备出现什么症状表现的时候，可以直接查库得到可能的故障以及对应的解决方案
        -3-. 智能医疗辅助系统/网上自助医疗诊断系统/辅助教学系统：从医院的诊疗记录中抽取出病症的表现的，病症的名称，病症的解决办法以及可能存在的后续病症等实体，构建实体与实体之间的关系，保存到数据库即可；直接基于病人的表征体现定位可能的疾病，从而得到需要的诊疗方案(如何检查、如何治疗<药品、手术、注意事项>)
        -4- 聊天机器人/智能客服/语音的智能客服：针对特定领域构造智能的客服
            意图识别 + 命名实体识别 + slot槽位设计
            -a-. 针对用户的问题，判断对应的意图，当前流程仅处理特定意图
            -b-. 对特定意图的场景进行分析，判断当前意图可能存在的实体信息,结合业务设计槽位，最后基于槽位信息进行业务数据的逻辑处理
            NOTE: 针对用户的问题，进行意图识别，然后根据需要提取对应的实体，并按照对应的格式槽位进行填充
            比如：
                交通车票查询的槽位设计案例：A日期从B到C的D票还有没有?
                    系统就需要从文本中提取出A日期、B起始地点、C目的地、D交通方式
                    eg:
                        从上海去张家界的火车票明天还有吗？
                        买一张明天上海开出到张家界的火车票
                        买一张明天到张家界的火车票
                    判断的实体结果: 上海 --> 起始地点
                                    张家界 --> 目的地
                                    火车 --> 交通方式
                                    明天 --> 日期
                                NOTE: 代码逻辑上再对实体进行转换处理,比如日期明天转换为具体日期
                eg:
                    问句1: 还款日期是几号?
                    问句2: 最迟可以时候还款?

# 查询
LOAD CSV FROM 'file:///artists2.csv' AS line

RETURN a;
# insert or update：基于csv进行数据的查询、更新以及插入
LOAD CSV FROM 'file:///artists2.csv' AS line
MERGE (a:Artist {id:toInteger(line[0])})
ON CREATE SET
	a.id = toInteger(line[0]),
	a.name = line[1],
	a.year = toInteger(line[2]),
	a.age = toInteger(line[3]),
	a.created = timestamp()
ON MATCH SET
	a.year = toInteger(line[2]),
	a.age = toInteger(line[3])
RETURN a;

命名实体识别
    功能/需求：从给定的文本中，抽取/识别出来业务关心的实体对象(实体单词片段)
    应用场景：
        搜索：
            -1. 用户给定了一段文本query进行搜索
            -2. query的处理逻辑/query理解逻辑：
                --2.1 分词、词性标注、命名实体识别、关系抽取、意图识别、纠错.....
                --2.2 分词：基础 + 可以词语的组合进行关键词的匹配(可以结合词性....)
                --2.3 意图识别 + 命名实体识别 + 关系抽取： 进行精准信息的匹配
                    意图识别：对query进行分类，比如类别包括：属性的查询、汇率的转换、度量单位转换、其它查询
                        属性的查询：
                            命名实体识别：主体、属性类型
                            关系抽取：
                                不太需要 --> 命名实体识别 + 意图识别 + 单主体/单属性的要求(业务) 已经将实体之间的关系抽取出来了
                                需要 ---> 针对多主体、多属性的情况考虑
                            获取结果：
                                如果提取出来对应的“实体-属性”信息，直接查询数据库即可
                                如果没有提取出对应的实体-属性信息，那么直接走默认的(当前这个链路直接返回空)
                            eg:
                                成龙的妻子是谁 ---> 提出出实体"成龙", 获得当前query的需求是判断关系"妻子"
                        汇率的转换：
                            命名实体识别：源汇率类型、目标汇率类型、源汇率金额、目标汇率的金额
                        度量单位转换：
                            命名实体识别：源单位、目标单位、源度量值、目标度量值、度量类型
                        其它查询 + 特殊查询链路走不通：
                            分词 + 关键词匹配 + 语义匹配.....
            -3. 基于query的处理结果，从海量的原始数据中获取数据/匹配数据，得到候选网页/结果的列表
            -4. 将候选的结果列表进行排序(可以参考query以及当前用户的历史行为)，最终返回Top K显示在页面上
        聊天机器人/智能客服/智能辅助诊断系统:
            NOTE: 特点领域的聊天机器人，eg: 金融、医疗....
            -1. 用户给定一个question问题文本
            -2. question文本分析/理解
                eg:
                    a. 我的信用卡还有多久过期?
                    b. 信用卡什么时候过期?
                    c. 信用卡过期了吗?
                    d. 我这期需要还多少钱?
                    e. 我这期的账单是多少?
            -3. 获取最匹配的answer结果返回显示即可
            NOTE:
                智能辅助诊断系统:
                    如何辅助诊断?
                        CV: 能够自动的针对CT、B超、X光等"照片"进行自动的预测判断是否患病(正常/患病(疾病1、疾病2、.... + 患病位置))
                        NLP: 类似聊天机器人/搜索
                            医生输入病人的查体信息(文本类型的), 模型从查体信息中获取症状、疾病历史等信息，结合关系抽取的结果，从数据库直接匹配结果即可
                                eg:
                                    病症A + 病症B --查询得到--> 检查方式1
                                    检查方式1 ---检查 + 分析---> 检查结论A
                                    病症A + 病症B + 检查结论A + 其它检查结论B --> 疾病类型A
                                    疾病类别A + 疾病历史 ----> 治疗方式

命名实体识别实现方式：
    eg:
        输入：暑假的时候，我准备从上海出发去黑龙江游玩，预计三到五天的时间，黑龙江玩好后，直接回长沙。
        输出：
            [
                {"type":"Loc", "span":"上海", "start":10, "end":11},
                {"type":"Loc", "span":"黑龙江", "start":15, "end":17},
                {"type":"Loc", "span":"黑龙江", "start":31, "end":33},
                {"type":"Loc", "span":"长沙", "start":41, "end":42}
            ]
    实现方式一：基于字典匹配/规则匹配的一些逻辑方式来实现
    实现方式二：序列标注任务(Token分类模型)/子Token文本序列的分类
        方法1: 针对每个Token预测BMESO/BISO类型信息
            eg:
                x: 湖 南 张 家 界 的 美 食 有 什 么
                y: B-LOC M-LOC M-LOC M-LOC E-LOC O B-Attr E-Attr O O O
                note：预测类别数目就是 1 + 4 * name_entity_class_number(实体类别数目)
                note: 这种方式不适合实体嵌套的场景
                    {
                        'token': ['湖', '南', '张', '家', '界', '的', '美', '食', '有', '什', '么'],
                        'span': [
                            {'type': 'Loc', 'start': 0, 'end': 1},
                            {'type': 'Loc', 'start': 2, 'end': 4},
                            {'type': 'Loc', 'start': 0, 'end': 4},
                            {'type': 'Attr', 'start': 6, 'end': 7}
                        ]
                    }
                模型结构：
                    Token Embedding + Token Classify
                    Token Embedding可以选择：
                        静态词向量: nn.Embedding
                        动态词向量: ELMo(nn.Embedding+Bi-LSTM)、Transformer Encoder、BERT、GPT、BERT+Bi-LSTM、GPT+LSTM....
                    Token Classify可选选择:
                        FC + Softmax    + argmax：
                            针对每个token进行类别的判断(每个token独立判断属于 1+4*name_entity_class_number 个类别的中那一个类别)
                        FC + CRF        + viterbi:
                            在Softmax的基础上考虑类别与类别之间的转换关系来最终决定每个token对应的预测类别
        方式2: 针对每个Token预测对象的类别信息(指针网络&片段网络)
            片段网络：
                'token': ['湖', '南', '张', '家', '界', '的', '美', '食', '有', '什', '么']
                直接判断，所有的子片段对应的类别是什么(实体 + 非实体，eg: Loc、Attr、O....)
                    湖、南、张、家、界、的、美、食、有、什、么
                    湖南、南张、张家、家界、界的、的美、美食、食有、有什、什么
                    湖南张、南张家、张家界、家界的、界的美、的美食、美食有、食有什、有什么
                    湖南张家、南张家界、张家界的、家界的美、界的美食、的美食有、美食有什、食有什么
                    湖南张家界、南张家界的、张家界的美、家界的美食、界的美食有、的美食有什、美食有什么
                    ......

                    计算量大(和候选片段的最大允许长度有关)，有可能没办法覆盖全所有的实体(和候选片段的最大允许长度有关)

NOTE: 一般情况下，NLP领域的模型训练都是采用迁移学习的方式
    迁移学习：使用开源的、在通用领域中预训练模型作为当前业务场景中的模型初始化参数
    针对迁移过来的模型参数，一般采用下列方式进行处理：
        -1. 可以考虑将迁移过来的参数冻结，不进行参数更新: requires_grad = False
        -2. 直接将迁移过来的参数和其它参数同等处理，进行相同的参数更新逻辑
        -3. 针对迁移过来的参数进行微调，针对其它参数进行正常的更新逻辑
            微调: 在已有的参数值的基础上仅更改一点点的值，eg：原始的参数值为0.35624，更新后就是: 0.35625

    代码结构：
        整体结构：数据处理、模型结构、训练、持久化、部署(推理代码、Http API接口代码、Dockerfile...)等等.....
    数据处理:
        一般NLP中的数据处理：分词/分Token、Token转换为对应的id、类别名称到id的映射
        额外可能支持/处理的(数据增强):
            -1. 针对实体位置的token直接替换成其它同类型的实体token
                eg: 还有从上海到长沙的高铁票吗?
                    随机替换: 上海、长沙、高铁票
                    -->
                        还有从上海到北京的飞机票吗?
                        还有从深圳到长沙的汽车票吗?
                        还有从上海浦东到上海静安的飞机票吗?
                        ......
            -2. 针对每个token/字采用同形或者同音的字进行替换，或者替换成拼音或者替换成UNK
                eg: 还有从上海到长沙的高铁票吗?
                    --->
                        患有从上海到长沙的高铁票吗?
                        huanyou从shagnhai到长沙的高铁票吗?
                        还有从上海到长沙的高铁票吗?
                        上海到长沙的高铁
    模型结构:
        一般NLP中常用的结构都是：
            Embedding + 动态词向量(Bi-LSTM、Bert、GPT、T5、Transformer....) + 分类结构
            输入: [N,T] N个样本，每个样本有T个token id --> 对应到Dataset中就有对应的分词+token id的映射
            模型输出: [N,T,num_classes] N个样本，每个样本有T个token，每个Token对应num_classes个类别的置信度
    训练&评估&持久化：
        迭代循环进行训练、评估、持久化处理
            对train_dataloader进行循环处理，针对每个批次获取前向结果以及反向更新；
            对eval_dataloader进行循环处理，得到每个批次的预测结果以及实际标签，计算两者之间的评估指标：Token分类评估指标(准确率、F1...)、实体片段的评估指标(准确率、Recall...)

关系抽取:
    定义/功能：在实体识别之后，判断实体之间存在什么类型的关系 ---> 也就是对实体组/实体对进行分类操作
    基本概念:
        实体1 --关系--> 实体2
        关系的表达，一般采用三元组来表达: (实体1,关系,实体2)
        实体1我们称为主体，关系是从这个实体出发的, eg: 姚明 --妻子--> 叶莉，姚明就是主体
        实体2我们成为客体，关系是到这个实体的，eg: 姚明 --妻子--> 叶莉，叶莉就是客体
            (姚明，妻子，叶莉)  姚明 --妻子--> 叶莉
            (叶莉，丈夫，姚明)  叶莉 --丈夫--> 姚明
            (姚明，身高226cm)   姚明 --属性--> 身高226cm
    eg:
        今年暑假，我准备去西安、新疆这两个地方去玩，但是不知道能不能从上海坐火车过去?

spert:（片段网络）
    最核心的思路/流程：
        a. 从给定文本中进行窗口滑动，得到所有的“候选实体片段”；
            ---> 训练的时候，候选实体片段分为两类(正样本<具体实体类别>、负样本)；推理的时候暴力遍历所有候选片段，需要通过模型判断属于正样本还是负样本
        b. 将原始文本输入bert模型，得到每个token对应的特征向量 --> 模型迁移；
        c. 实体的分类判断：针对每个 "候选实体片段" 提取对应的特征向量(token片段的特征向量、片段长度特征向量、文本特征向量)，对提取的特征向量进行全连接，得到预测属于各个类别的置信度
            ---> 训练的时候，基于置信度和实际的标签值计算损失；推理的时候，基于置信度进行过滤，得到属于实体的片段(实体片段/正样本)
        d. 基于实体的正样本(实体片段)，进行交叉组合得到所有的"候选实体-关系组合"
            ---> 训练的时候，由于实体片段类型是已知的，所以可以直接构造
            ---> 推理的时候，需要基于实体预测的结果进行构造
        e. 关系的分类判断：针对每个 "候选实体-关系组" 提取对应的特征向量(实体1 bert特征向量+长度特征、实体2 bert特征向量+长度特征、实体1和实体2之间的token bert特征向量)， 对提取的特征向量进行全连接，得到预测属于各个关系类别的置信度
            ---> 训练的时候，基于置信度和实际的标签值计算损失(多分类)；推理的时候，基于置信度/概率进行过滤，得到属于关系的实体组合
    参考:
        https://www.modb.pro/db/472588
        https://github.com/lavis-nlp/spert
        https://blog.csdn.net/Wang_XB_3434/article/details/131345012

    缺陷：
		1. 非常强的依赖span片段大小，而且span的片段大小是先验值，针对异常的情况，很难覆盖
		2. 当span先验长度给定比较长的时候，模型的计算量会增加
		3. 长度会影响实体预测过程中候选实体的数量，从而影响模型的计算量,最终影响实体的预测结果；
		4. 预测为实体的数量会影响关系预测过程中，候选关系的数量，从而影响关系的计算量；
    可选的优化点:
        a. 候选实体的产生方式上
        b. 损失上的优化
        c. 网络结构上

            _get_logits_processor 方法:-->主要在do_sample=True的时候生效(目的是为了生成数据的多样性)  --> 在步骤6的生效
                temperature: 温度系数，要求取值范围为: (0, 1]  也可以是一个大于1的值
                    将模型预测的置信度除以给定的temperature
                    用来控制随机采样的时候的一个多样性，针对一个相同的输入，如果你期望模型生成的内容是比较固定的，那么将该参数调小(小于1 eg:0.01), 如果你希望返回结果相对来讲是不固定的，可以考虑该参数调大(大于1)
                top_k: Top K系数
                    针对每个样本，仅保留最大的K个置信度，并将其它token对应的置信度重置为-inf
                    top_k越大，表示随机采样时候涉及到样本越多，生成越多样性
                    top_k越小，表示随机采样时候涉及到样本越少，生成就越固定
                top_p: 取值范围(0,1.0)
                    针对每个样本，预测概率从小到大排序后，概率累计值小于1-top_p的预测置信度全部重置为-inf
                    top_p越大，保留的token越多，生成就越随机
                    top_p越小，保留的token越少，生成就越固定
                typical_p:
                    和参数top_p类似, 区别在于排序的逻辑不一样: top_p中是直接对原始的置信度/概率排序, typical_p对修正后的置信度/概率进行排序
                    修正方式:
                        normalized = torch.nn.functional.log_softmax(scores, dim=-1)
                        p = torch.exp(normalized)
                        ent = -(normalized * p).nansum(-1, keepdim=True)
                        shifted_scores = torch.abs((-normalized) - ent)
                epsilon_cutoff:
                    针对每个样本的每个token而言，如果softmax概率值小于epsilon_cutoff，那么该token对应的置信度重置为-info
                eta_cutoff:
                    针对每个样本的每个token而言，如果softmax概率值小于某个锚定概率值(eta)，那么该token对应的置信度重置为-info
                    锚定概率值计算方式:
                        entropy = torch.distributions.Categorical(logits=scores).entropy()
                        eta = torch.min(eta_cutoff, torch.sqrt(eta_cutoff) * torch.exp(-entropy))[..., None]

        -1. contrastive search 对比检索
            选择当前逻辑策略: num_beams=1、do_sample=False、top_k>1、penalty_alpha>0、不是策略7
            逻辑：
                1. 在预测当前时刻token的时候，采用以下执行逻辑:
                    a. 基于当前的输入，获取当前最后一层的高阶特征向量U[N,768]，以及top_k置信度最大的候选预测token id列表
                    b. 将top k的候选token id再次输入到模型中，得到每个token id对应的高阶特征向量V[N, 50, 768]
                    c. 计算U和V两个矩阵的余弦相似度(针对每个样本，独立计算上一层的高阶特征向量和当前50个高阶特征向量之间的相似度)
                    d. 将候选的top k个token对应概率值和相似度进行加权，得到加权后的概率值
                    d. 选择概率值最高的对应的token id作为当前时刻的预测结果（最终选择的token不仅考虑预测置信度要大，还要求连续两个时刻decoder最终的高阶特征向量也需要相似度）
        ☆-2. greedy search 贪心检索策略  -- 需要理解  --> 默认策略
            选择当前逻辑策略: num_beams=1、do_sample=False、top_k为None或者top_k=1或者penalty_alpha为None或者penalty_alpha<=0、不是策略7
            逻辑：
                每个时刻对应的预测token均选择当前时刻预测概率最大的对应token
        ☆-3. sample 抽样 ---> 大语言模型中，该策略使用的比较多   -- 需要理解
            选择当前策略的逻辑: 不是策略7、num_beams=1、do_sample=True
            逻辑：
                先对模型输出的置信度进行重置/转换计算，仅保留TopK的置信度(最大的)，其它token的置信度重置为-inf
                将重置后的预测置信度转换为softmax概率值(-inf的位置概率为0)
                最终基于概率值进行随机采样(均匀分布)，采样结果就是预测的下个token
        -4. assisted generation
            选择当前策略的逻辑: assistant_model或者prompt_lookup_num_tokens非None、并且其它参数决定策略为2或者3
        ☆-5. beam search 集束检索  -- 需要理解
            选择当前策略的逻辑: 不是策略7、num_beams>1、num_beam_groups≤1、do_sample=False
            逻辑:
                在每个时刻选择num_beams个预测概率最大的token(选择的时候需要考虑之前选择的token --> 选择的是和之前token组成的序列概率最大化)
                在每一个token预测的时候，选择若干个最有可能的候选项，所以在每次token选择的时候，都是在之前选择的基础上，从当前序列置信度最大的角度进行选择当前预测token
        ☆-6. beam sample ---> 大语言模型中，该策略使用的比较多   -- 需要理解
            选择当前策略的逻辑: 不是策略7、num_beams>1、num_beam_groups≤1、do_sample=True
            逻辑：在beam search的基础上，更改选择token的逻辑，在beam search中，每次是选择最有可能的token作为预测值，但是在beam sample中是随机选择
                先对模型输出置信度进行log-softmax概率转换
                在对模型输出的log-softmax概率值进行重置计算，仅保留TopK的置信度(最大的)，其它token的重置为-inf
                将重置后的log-softmax概率值转换为softmax采样概率值
                最终基于采样概率值进行随机采样(均匀分布)，采样结果就是预测的下个token --> 和sample相比，相当于每次采样更多的token(num_beams)
        -7. constrained beam search
            选择当前策略逻辑: constraints 或者 force_words_ids 非None
        -8. group beam search
            选择当前策略的逻辑: 不是策略7、num_beams>1、num_beam_groups>1
            逻辑：
                和beam search的唯一区别在于，beam search只有一个组; group beam search是将计算分割为多个组分别来计算；为了防止各个组的结果重复；基于参数diversity_penalty做了概率置信度的修正(如果在上一个beam中出现过，那么在当前时刻对应的组中，token的置信度减小diversity_penalty*出现的频次)
